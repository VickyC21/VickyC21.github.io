# 大模型开发工程师数据结构与算法入门讲义：从数组到复杂度分析

数据结构解决“数据如何组织”，算法解决“基于这些数据如何高效完成任务”。对于大模型开发工程师，这不是只为面试准备的题库：聊天历史用列表保存，模型配置和缓存用字典索引，工具调用的流程可以用栈或队列理解，RAG 知识的关联可看作图，性能问题则需要用复杂度分析提前判断风险。

本文面向 Python 初学者。目标不是背下所有模板，而是建立一条稳定的思路：先识别数据与操作，再选择合适结构，最后用时间和空间复杂度验证方案是否合理。

> 运行环境：Python 3.11+，示例只使用标准库。请亲手运行、改动输入，并观察输出。算法学习的关键是画过程、写过程、验证过程。

## 2. 先建立算法思维

### 2.1 什么是“输入规模”

复杂度中的 `n` 不是固定数字，而是输入规模。例如：

- 在 10 条聊天记录中查找某一条，`n` 是消息数量；
- 在 100 万份文档里搜索文档 ID，`n` 是文档数量；
- 在一个知识图谱中遍历关联节点，`V` 是节点数，`E` 是边数。

同一段代码在数据量很小时看不出差异，数据量扩大后才会暴露问题。一个每次扫描整个列表的函数，处理 10 条数据时很快，处理 100 万条数据时可能会成为接口延迟的主要来源。

### 2.2 好算法的四个问题

面对一个问题，先不要急着写循环，依次问：

1. **数据是什么？** 例如文档 ID、消息、任务、节点关系。
2. **最频繁的操作是什么？** 查找、插入、删除、排序、按顺序处理，还是按关系扩散？
3. **输入是否有约束？** 是否已排序、是否允许重复、是否可能为空、是否需要保持原顺序？
4. **正确性的边界是什么？** 找不到时返回什么，输入非法时如何处理，是否会修改原数据？

以“判断一个请求 ID 是否已处理”为例：数据是 ID 集合，最频繁操作是“是否存在”。列表可以做，但每次要顺序比较；集合或字典更符合这个操作。

```python
processed_request_ids = {"req_001", "req_002"}
request_id = "req_002"

if request_id in processed_request_ids:
    print("重复请求，跳过处理")
else:
    processed_request_ids.add(request_id)
    print("开始处理")
```

## 3. 复杂度分析：衡量增长，而不是计时一次

### 3.1 Big O 的直觉

大 O 表示“当输入不断增大时，运行成本的增长趋势”。它通常忽略常数和低阶项，关注最主要的增长项。

| 复杂度 | 名称 | `n` 扩大 10 倍时的直觉 | 常见例子 |
| --- | --- | --- | --- |
| `O(1)` | 常数时间 | 基本不变 | 字典按键取值、数组按下标取值 |
| `O(log n)` | 对数时间 | 增长很慢 | 二分搜索 |
| `O(n)` | 线性时间 | 约扩大 10 倍 | 遍历列表 |
| `O(n log n)` | 线性对数 | 比线性略高 | 高效比较排序 |
| `O(n^2)` | 平方时间 | 约扩大 100 倍 | 两层完整循环比较 |
| `O(2^n)` | 指数时间 | 很快不可用 | 穷举所有子集 |

例如下面的函数只检查列表中是否包含目标值。最坏情况下目标在最后，或根本不存在，因此需要比较 `n` 次，时间复杂度是 `O(n)`。

```python
def contains_linear(values: list[str], target: str) -> bool:
    """按顺序查找目标值。

    Args:
        values: 待查找的字符串列表。
        target: 要查找的目标字符串。

    Returns:
        找到目标时返回 True，否则返回 False。
    """
    for value in values:
        if value == target:
            return True
    return False
```

### 3.2 最好、平均与最坏情况

若目标刚好位于第一个位置，`contains_linear()` 很快结束；若目标不存在，则必须扫描全部元素。面试和容量评估常关注最坏情况，因为线上请求不能假设总是幸运。

哈希表查询常说平均 `O(1)`，但这不是数学承诺：发生大量哈希冲突、哈希函数质量差或攻击性输入时会退化。Python 内置 `dict` 和 `set` 的实现已经处理了很多实际问题，日常工程中可将其查找和插入理解为平均 `O(1)`，但不应写出依赖“绝对恒定时间”的安全逻辑。

### 3.3 空间复杂度

空间复杂度表示算法额外需要多少内存。下面函数创建了一个和输入长度同级别的新列表，因此额外空间是 `O(n)`。

```python
def normalize_questions(questions: list[str]) -> list[str]:
    """去除问题两端空白，返回新列表而不修改原列表。"""
    return [question.strip() for question in questions]
```

相反，原地修改列表通常只使用 `O(1)` 的额外空间，但会改变调用方数据。性能与可维护性需要一起权衡，不能只追求一个指标。

### 3.4 如何分析循环

- 一层从头到尾循环：通常是 `O(n)`；
- 两层都完整扫描同一个规模的数据：通常是 `O(n^2)`；
- 每轮将范围减半：通常是 `O(log n)`；
- 先排序再扫描：通常由排序主导，即 `O(n log n)`；
- 两段先后执行的代码相加，保留增长最快项，例如 `O(n) + O(n^2) = O(n^2)`。

```python
def find_duplicate_slow(values: list[str]) -> bool:
    """使用两两比较寻找重复元素，时间复杂度为 O(n^2)。"""
    for left_index in range(len(values)):
        for right_index in range(left_index + 1, len(values)):
            if values[left_index] == values[right_index]:
                return True
    return False


def find_duplicate_fast(values: list[str]) -> bool:
    """使用集合寻找重复元素，平均时间复杂度为 O(n)。"""
    seen: set[str] = set()
    for value in values:
        if value in seen:
            return True
        seen.add(value)
    return False
```

第二个实现并不是“语法更高级”，而是将“已经见过哪些值”的状态存入哈希集合，使每次判断不再重复扫描历史数据。

## 4. 数组：连续、可索引的数据序列

严格说，Python 的 `list` 是可动态扩容的数组，不是传统意义上固定长度的数组。它最重要的能力是：**通过下标快速定位元素**。

```python
models = ["small", "medium", "large"]

print(models[0])   # small
print(models[-1])  # large
models[1] = "reasoning"
print(models)
```

### 4.1 常见操作与复杂度

| 操作 | Python 写法 | 时间复杂度 | 原因 |
| --- | --- | --- | --- |
| 按下标读取/修改 | `items[index]` | `O(1)` | 可直接计算元素位置 |
| 尾部追加 | `items.append(x)` | 均摊 `O(1)` | 偶尔扩容，长期平均很快 |
| 尾部删除 | `items.pop()` | `O(1)` | 不需要移动其他元素 |
| 中间插入 | `items.insert(i, x)` | `O(n)` | 后续元素需要整体右移 |
| 中间删除 | `items.pop(i)` | `O(n)` | 后续元素需要整体左移 |
| 判断是否存在 | `x in items` | `O(n)` | 逐个比较 |

“均摊 `O(1)`”表示少数 `append()` 会因扩容复制旧元素而较慢，但许多次追加的平均成本仍接近常数。

### 4.2 示例：保留最近聊天历史

聊天服务常保留最近若干轮消息。若只需在末尾新增、从开头丢弃，列表能够工作；但如果历史很长且每次都 `pop(0)`，会移动所有剩余元素，成本为 `O(n)`。后文的队列会给出更合适结构。

```python
def keep_recent_messages(messages: list[dict[str, str]], limit: int) -> list[dict[str, str]]:
    """返回最近 limit 条消息。

    Args:
        messages: 按时间顺序排列的消息列表。
        limit: 保留的最大消息数，必须为非负数。

    Returns:
        新的消息列表；不会修改传入的 messages。

    Raises:
        ValueError: 当 limit 为负数时抛出。
    """
    if limit < 0:
        raise ValueError("limit 不能为负数")
    return messages[-limit:] if limit else []


history = [
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好，请问有什么可以帮助你？"},
    {"role": "user", "content": "解释 RAG"},
]
print(keep_recent_messages(history, 2))
```

### 4.3 双指针：减少不必要的嵌套循环

在一个已排序数组中找两个数之和，可使用左右两个指针。左侧太小就右移左指针，右侧太大就左移右指针；每个元素最多被指针经过一次，时间复杂度是 `O(n)`。

```python
def find_pair_with_sum(sorted_values: list[int], target: int) -> tuple[int, int] | None:
    """在升序列表中寻找和为 target 的两个数。

    Args:
        sorted_values: 已按升序排列的整数列表。
        target: 目标和。

    Returns:
        找到时返回两个下标；找不到时返回 None。
    """
    left = 0
    right = len(sorted_values) - 1

    while left < right:
        current_sum = sorted_values[left] + sorted_values[right]
        if current_sum == target:
            return left, right
        if current_sum < target:
            left += 1
        else:
            right -= 1
    return None


numbers = [1, 3, 4, 7, 10, 12]
print(find_pair_with_sum(numbers, 13))  # (0, 5)
```

前提是列表已排序。不要把双指针模板套到无序数据上，否则“移动哪一侧会更接近目标”的推理不成立。

## 5. 链表：通过节点连接的数据结构

链表由一个个节点构成。每个节点保存自己的值以及“下一个节点”的引用。它不要求元素在内存中连续，因此已知节点位置时插入或删除不必移动后续元素。

```text
head -> [A | next] -> [B | next] -> [C | None]
```

Python 标准库没有直接给出教学用链表；工程中通常优先选择内置 `list` 或 `deque`。学习链表的价值在于理解“随机访问”和“局部连接修改”的取舍。

### 5.1 最小单链表实现

```python
from dataclasses import dataclass


@dataclass
class ListNode:
    """单链表的一个节点。"""

    value: str
    next: "ListNode | None" = None


def print_linked_list(head: ListNode | None) -> None:
    """从头节点开始输出链表内容。"""
    current = head
    values: list[str] = []

    while current is not None:
        values.append(current.value)
        current = current.next

    print(" -> ".join(values))


third = ListNode("C")
second = ListNode("B", next=third)
first = ListNode("A", next=second)
print_linked_list(first)
```

遍历时必须保留一个 `current` 指针，并在每一轮移动到 `current.next`。若忘记移动，会无限循环；若一开始覆盖了 `head`，会丢失链表入口。

### 5.2 插入与删除

若要在节点 `A` 后插入 `X`，先让 `X` 指向原本的下一个节点，再让 `A` 指向 `X`：

```text
原来：A -> B
第一步：A -> B，X -> B
第二步：A -> X -> B
```

```python
def insert_after(node: ListNode, value: str) -> None:
    """在给定节点后插入新节点。

    Args:
        node: 已知存在的目标节点。
        value: 新节点保存的值。
    """
    node.next = ListNode(value=value, next=node.next)


insert_after(first, "X")
print_linked_list(first)  # A -> X -> B -> C
```

这是 `O(1)`，但前提是你已经拿到了 `node`。若你只知道“要找值为 B 的节点”，仍然需要从头遍历，查找成本为 `O(n)`。

### 5.3 数组与链表的取舍

| 需求 | 数组 / `list` | 链表 |
| --- | --- | --- |
| 按第 `i` 个元素读取 | 强，`O(1)` | 弱，`O(n)` |
| 已知位置后插入/删除 | 通常 `O(n)` | `O(1)` |
| CPU 缓存友好、遍历常数小 | 通常更好 | 节点分散，通常较差 |
| Python 日常业务代码 | 首选 | 很少直接手写 |

初学者常误以为链表“插入快，所以更高级”。结构选择取决于真实操作。若业务需要按下标读消息、批量遍历、序列化为 JSON，Python 列表往往更简单、更快也更清楚。

## 6. 哈希表与集合：用键快速定位数据

哈希表将键经过哈希函数映射到存储位置。Python 的 `dict` 是哈希表，`set` 是只保存键的哈希集合。

```python
model_prices = {
    "small": 0.5,
    "reasoning": 3.0,
}
print(model_prices["small"])

allowed_roles = {"system", "user", "assistant"}
print("tool" in allowed_roles)  # False
```

### 6.1 `dict` 和 `set` 何时使用

- 需要“名称 -> 信息”的映射：使用 `dict`，如 `document_id -> 文档元数据`；
- 只需要判断是否存在、去重：使用 `set`，如已处理请求 ID；
- 需要保持输入顺序并允许重复：使用 `list`。

Python 3.7+ 的字典保持插入顺序，但不要把“可按插入顺序遍历”误解为它适合下标随机访问；字典的核心仍是按键查询。

### 6.2 示例：统计词频

```python
def count_words(text: str) -> dict[str, int]:
    """统计以空白分隔的词出现次数。

    Args:
        text: 待统计文本。

    Returns:
        从小写单词到出现次数的映射。
    """
    counts: dict[str, int] = {}

    for word in text.lower().split():
        counts[word] = counts.get(word, 0) + 1

    return counts


print(count_words("RAG rag LLM RAG"))
# {'rag': 3, 'llm': 1}
```

`get(word, 0)` 表示键不存在时先使用默认值 `0`。这比每轮先写 `if word in counts` 更紧凑，但理解其含义比记住写法更重要。

### 6.3 示例：两数之和的哈希解法

对于无序数组，想找出和为目标值的两个元素。暴力做法用两层循环，`O(n^2)`；哈希表做法将已见数字映射为其下标，每轮只查一次“需要的补数”，平均 `O(n)`。

```python
def find_pair_with_hash(values: list[int], target: int) -> tuple[int, int] | None:
    """在无序整数列表中找出和为 target 的两个下标。

    Args:
        values: 无序整数列表。
        target: 目标和。

    Returns:
        找到时返回一对不同下标，找不到时返回 None。
    """
    index_by_value: dict[int, int] = {}

    for index, value in enumerate(values):
        needed = target - value
        if needed in index_by_value:
            return index_by_value[needed], index
        index_by_value[value] = index

    return None


print(find_pair_with_hash([2, 7, 11, 15], 9))  # (0, 1)
```

注意顺序：先查 `needed`，后保存当前 `value`，可确保不会把同一个元素使用两次。例如列表只有 `[3]`、目标是 `6` 时，函数不会错误地返回 `(0, 0)`。

### 6.4 哈希表的边界与常见错误

1. 字典键必须可哈希。`str`、`int`、元组通常可以；`list`、`dict` 不可以。
2. `mapping[key]` 在键不存在时抛 `KeyError`；处理外部输入时常用 `mapping.get(key)` 或显式校验。
3. `set` 会去重，不能用于需要保留重复次数或原始顺序的业务。
4. 不要用 `list` 做大规模成员测试后才“为了省事”继续扫描；这是典型的可优化热点。

## 7. 栈：后进先出（LIFO）

栈的原则是“最后放进去的，最先取出来”，如同一叠盘子。常见操作：

- `push`：压入元素；
- `pop`：弹出顶部元素；
- `peek`：查看顶部而不弹出。

Python 中用 `list.append()` 和 `list.pop()` 实现栈最自然，二者都在尾部操作，通常是 `O(1)`。

```python
stack: list[str] = []
stack.append("请求进入")
stack.append("开始检索")
stack.append("调用模型")

print(stack.pop())  # 调用模型
print(stack[-1])    # 开始检索，查看栈顶
```

### 7.1 示例：括号匹配

括号是否匹配是栈的经典问题。遇到左括号就入栈；遇到右括号时，必须和栈顶左括号配对。若栈空或类型不匹配，表达式非法；结束后栈必须为空。

```python
def has_balanced_brackets(text: str) -> bool:
    """检查文本中的圆括号、方括号和花括号是否正确配对。"""
    opening = {"(", "[", "{"}
    matching_opening = {
        ")": "(",
        "]": "[",
        "}": "{",
    }
    stack: list[str] = []

    for char in text:
        if char in opening:
            stack.append(char)
        elif char in matching_opening:
            if not stack or stack.pop() != matching_opening[char]:
                return False

    return not stack


print(has_balanced_brackets("{[()]}"))  # True
print(has_balanced_brackets("([)]"))    # False
print(has_balanced_brackets("(()"))     # False
```

这段代码只扫描每个字符一次，时间复杂度 `O(n)`；最坏情况下所有字符都是左括号，栈保存 `n` 个字符，额外空间 `O(n)`。

### 7.2 栈的工程用途

- 函数调用栈与异常回溯；
- 编辑器的撤销操作；
- JSON、表达式或嵌套标签解析；
- 深度优先搜索中的待访问节点；
- Agent 工作流中需要后退或恢复的步骤记录。

## 8. 队列：先进先出（FIFO）

队列的原则是“先进入的，先处理”，像排队等候。常见操作：

- `enqueue`：从队尾加入；
- `dequeue`：从队头取出。

不要用 `list.pop(0)` 实现高频出队，因为它是 `O(n)`。Python 应使用 `collections.deque`：在两端追加和弹出都是 `O(1)`。

```python
from collections import deque

queue = deque(["task_001", "task_002"])
queue.append("task_003")
print(queue.popleft())  # task_001
print(list(queue))
```

### 8.1 示例：按到达顺序处理任务

```python
from collections import deque


def process_tasks(tasks: list[str]) -> list[str]:
    """以先进先出顺序处理任务，返回处理记录。"""
    pending = deque(tasks)
    completed: list[str] = []

    while pending:
        task = pending.popleft()
        completed.append(f"已处理：{task}")

    return completed


print(process_tasks(["解析文档", "生成向量", "写入索引"]))
```

这里每个任务入队、出队和记录各一次，时间复杂度是 `O(n)`。

### 8.2 双端队列与优先队列

- `deque` 支持两端操作，适合滑动窗口、普通队列和双端队列；
- 优先队列按优先级而不是到达顺序取出元素，Python 使用 `heapq`，常用于调度、Top K 和合并多个有序流；
- 队列本身不提供线程安全的任务系统。生产环境还需考虑持久化、重试、幂等、可观测性和故障恢复。

## 9. 树：分层关系的数据结构

树由节点和边组成，除根节点外，每个节点有一个父节点；一个节点可以有多个子节点。目录结构、JSON、HTML DOM、组织层级和决策流程都可用树表达。

```text
             根
          /      \
       检索      生成
      /   \        \
   召回   重排     输出
```

### 9.1 二叉树基本概念

二叉树中每个节点最多两个子节点，称为左子节点和右子节点。下面定义一个整数二叉树节点：

```python
from dataclasses import dataclass


@dataclass
class TreeNode:
    """二叉树节点，保存整数值及左右子节点。"""

    value: int
    left: "TreeNode | None" = None
    right: "TreeNode | None" = None


root = TreeNode(
    8,
    left=TreeNode(3, left=TreeNode(1), right=TreeNode(6)),
    right=TreeNode(10, right=TreeNode(14)),
)
```

### 9.2 深度优先搜索（DFS）

DFS 会先沿一条路径尽可能向下走，再回退到分叉处。递归写法简洁，因为函数调用栈天然保存了“尚未回来的路径”。

```python
def preorder_values(node: TreeNode | None) -> list[int]:
    """以前序遍历方式返回二叉树节点值。

    前序顺序为：当前节点、左子树、右子树。
    """
    if node is None:
        return []

    return [node.value, *preorder_values(node.left), *preorder_values(node.right)]


print(preorder_values(root))  # [8, 3, 1, 6, 10, 14]
```

上面写法易懂，但每层构造新列表的额外开销不适合大树。如下版本将结果列表作为参数传递，更接近 `O(n)` 的遍历实现：

```python
def collect_preorder(node: TreeNode | None, values: list[int]) -> None:
    """将前序遍历结果追加到调用方提供的列表。"""
    if node is None:
        return

    values.append(node.value)
    collect_preorder(node.left, values)
    collect_preorder(node.right, values)


result: list[int] = []
collect_preorder(root, result)
print(result)
```

遍历每个节点一次，时间复杂度为 `O(n)`；递归调用栈的空间复杂度是 `O(h)`，其中 `h` 是树高。极端退化成链表时 `h = n`，可能触发 Python 递归深度限制，此时应改用显式栈。

### 9.3 广度优先搜索（BFS）

BFS 按层访问节点：先根，再同层节点，再下一层。它需要队列保存“已经发现但尚未访问”的节点。

```python
from collections import deque


def level_order_values(root: TreeNode | None) -> list[int]:
    """按从上到下、从左到右的层序遍历返回节点值。"""
    if root is None:
        return []

    queue = deque([root])
    values: list[int] = []

    while queue:
        node = queue.popleft()
        values.append(node.value)

        if node.left is not None:
            queue.append(node.left)
        if node.right is not None:
            queue.append(node.right)

    return values


print(level_order_values(root))  # [8, 3, 10, 1, 6, 14]
```

BFS 和 DFS 都会访问每个节点一次，时间复杂度都是 `O(n)`。区别是访问顺序和内存形态：宽而浅的树在 BFS 中可能同时进入很多节点；深而窄的树在 DFS 中递归深度较大。

### 9.4 二叉搜索树（BST）

二叉搜索树满足：左子树所有值小于当前节点，右子树所有值大于当前节点。查找时每轮可以排除一侧子树，平衡时复杂度为 `O(log n)`；若树退化成一条链，则又变成 `O(n)`。

这说明数据结构的理论优势往往依赖额外条件。Python 中若只需排序和查找，通常使用 `list` 加排序或成熟库；不要为了一个查询需求手写未平衡的 BST。

## 10. 图：表达任意关系网络

图由顶点（节点）和边（关系）组成。与树不同，图允许一个节点有多个父节点，允许环，也允许节点之间没有连接。

工程中的例子：

- RAG 文档、实体、标签之间的关联；
- 服务依赖关系；
- 工作流步骤与状态迁移；
- 社交关系或推荐关系；
- 文件导入依赖。

### 10.1 邻接表

小型图常用邻接表：字典的键是节点，值是相邻节点列表。

```python
knowledge_graph = {
    "用户问题": ["查询改写", "向量检索"],
    "查询改写": ["向量检索"],
    "向量检索": ["重排"],
    "重排": ["模型生成"],
    "模型生成": [],
}
```

若图有 `V` 个节点、`E` 条边，邻接表需要约 `O(V + E)` 空间，适合边远少于 `V^2` 的稀疏图。邻接矩阵使用二维表，判断两点是否有边很快，但空间为 `O(V^2)`，大多数业务关系图不划算。

### 10.2 图的 DFS

图可能有环，因此 DFS 必须使用 `visited` 集合，防止在环中无限走下去。

```python
def dfs_reachable(graph: dict[str, list[str]], start: str) -> list[str]:
    """从起点执行深度优先搜索，返回首次访问的节点顺序。"""
    visited: set[str] = set()
    order: list[str] = []

    def visit(node: str) -> None:
        if node in visited:
            return

        visited.add(node)
        order.append(node)

        for neighbor in graph.get(node, []):
            visit(neighbor)

    visit(start)
    return order


print(dfs_reachable(knowledge_graph, "用户问题"))
```

### 10.3 图的 BFS：无权图最短路径

在每条边的成本相同的无权图中，BFS 第一次到达某节点的路径就是从起点出发的最少边数路径。队列保证所有距离为 1 的节点先于距离为 2 的节点被处理。

```python
from collections import deque


def shortest_path(graph: dict[str, list[str]], start: str, target: str) -> list[str] | None:
    """在无权有向图中使用 BFS 查找从 start 到 target 的最短路径。

    Args:
        graph: 邻接表形式的图。
        start: 起点。
        target: 终点。

    Returns:
        从起点到终点的节点路径；不可达时返回 None。
    """
    if start not in graph or target not in graph:
        return None

    queue = deque([start])
    parent: dict[str, str | None] = {start: None}

    while queue:
        node = queue.popleft()
        if node == target:
            break

        for neighbor in graph[node]:
            if neighbor not in parent:
                parent[neighbor] = node
                queue.append(neighbor)

    if target not in parent:
        return None

    path: list[str] = []
    current: str | None = target
    while current is not None:
        path.append(current)
        current = parent[current]

    path.reverse()
    return path


print(shortest_path(knowledge_graph, "用户问题", "模型生成"))
```

时间复杂度是 `O(V + E)`：每个节点最多入队一次，每条边最多检查一次。`parent` 同时承担“是否访问过”和“如何回溯路径”两个作用。

### 10.4 有权图与 Dijkstra

若不同边有不同成本，例如不同模型路由的延迟或费用，普通 BFS 不再保证成本最低。需要使用 Dijkstra 等最短路径算法，并通常以最小堆维护当前成本最小的候选节点。Dijkstra 要求边权非负；存在负权边时应考虑 Bellman-Ford 等算法。

初学阶段先掌握：**无权最短路径用 BFS；有非负权重的最短路径常用 Dijkstra**。不要只看函数名称，必须先确认问题的边权条件。

## 11. 排序：让数据形成有用顺序

排序是将数据按某个比较规则排列。排序后可以二分搜索、双指针扫描、合并区间，也能让日志、排行榜和候选结果更容易处理。

### 11.1 Python 中先用内置排序

Python 使用 Timsort，平均和最坏情况可理解为 `O(n log n)`，并且排序稳定：相等键的元素保留原始相对顺序。日常工程优先使用 `sorted()` 或 `list.sort()`，不要手写排序来替代可靠标准库。

```python
results = [
    {"document_id": "doc_1", "score": 0.72},
    {"document_id": "doc_2", "score": 0.91},
    {"document_id": "doc_3", "score": 0.72},
]

ranked = sorted(results, key=lambda item: item["score"], reverse=True)
print(ranked)

# list.sort() 原地修改，不创建新列表。
results.sort(key=lambda item: item["document_id"])
print(results)
```

### 11.2 冒泡排序：理解交换，不用于生产

冒泡排序反复比较相邻元素，顺序错误就交换。它便于理解，但最坏时间复杂度是 `O(n^2)`，大规模数据应避免。

```python
def bubble_sort(values: list[int]) -> list[int]:
    """返回升序排列的新列表，用于理解冒泡排序过程。"""
    result = values.copy()

    for end in range(len(result) - 1, 0, -1):
        swapped = False
        for index in range(end):
            if result[index] > result[index + 1]:
                result[index], result[index + 1] = result[index + 1], result[index]
                swapped = True
        if not swapped:
            break

    return result


print(bubble_sort([5, 1, 4, 2, 8]))
```

`swapped` 是一个有价值的优化：若某一轮完全没有交换，说明列表已经有序，可以提前结束。但它并没有改变最坏情况 `O(n^2)`。

### 11.3 归并排序：分治思想

归并排序将问题不断二分，分别排序，再把两个有序部分合并。分成小问题的层数是 `O(log n)`，每层合并总共处理 `n` 个元素，因此总时间为 `O(n log n)`，但需要 `O(n)` 辅助空间。

分治思想在算法中很重要：先把大问题拆成同类小问题，递归解决，再合并结果。二分搜索、快速排序和很多树问题都能看到它。

### 11.4 排序选择表

| 场景 | 推荐做法 | 原因 |
| --- | --- | --- |
| 普通业务排序 | `sorted()` / `.sort()` | 正确、稳定、性能成熟 |
| 只需最大的 K 个元素 | `heapq.nlargest()` | 不一定要完整排序 |
| 数据持续流入，反复取最小/最大 | `heapq` | 维护堆比每次全量排序更合适 |
| 教学理解交换过程 | 冒泡排序 | 直观但性能差 |
| 需要理解分治 | 归并排序 | 结构清晰，`O(n log n)` |

## 12. 搜索：在数据中定位目标

搜索不是只有一种算法。先问数据是否有序、是否需要精确匹配、是否需要返回位置、是否允许重复值，再选方法。

### 12.1 线性搜索

线性搜索适用于无序小数据或只搜索一次的场景。它简单且不需要预处理，但最坏为 `O(n)`。

```python
def find_document_index(documents: list[str], target: str) -> int | None:
    """在线性列表中返回目标文档的第一次出现位置。"""
    for index, document in enumerate(documents):
        if document == target:
            return index
    return None
```

### 12.2 二分搜索

二分搜索只适用于**已排序**数据。每次比较中间值后，排除一半不可能区域，所以时间复杂度为 `O(log n)`。

```python
def binary_search(sorted_values: list[int], target: int) -> int | None:
    """在升序整数列表中使用二分搜索目标值。

    Args:
        sorted_values: 已按升序排列的整数列表。
        target: 要寻找的整数。

    Returns:
        找到时返回一个匹配下标，找不到时返回 None。
    """
    left = 0
    right = len(sorted_values) - 1

    while left <= right:
        middle = (left + right) // 2
        middle_value = sorted_values[middle]

        if middle_value == target:
            return middle
        if middle_value < target:
            left = middle + 1
        else:
            right = middle - 1

    return None


values = [2, 5, 8, 12, 16, 23, 38]
print(binary_search(values, 16))  # 4
print(binary_search(values, 7))   # None
```

循环条件必须是 `left <= right`，因为最后可能只剩一个候选位置。更新时一定使用 `middle + 1` 或 `middle - 1`，否则边界不变会无限循环。

### 12.3 二分搜索的真实工程取舍

如果数据原本无序，先排序再二分搜索的总成本是 `O(n log n) + O(log n)`，约为 `O(n log n)`。只查一次时，线性搜索 `O(n)` 可能更好；需要在同一批静态数据上查询很多次时，预排序才值得。

若你主要按唯一 ID 查询，通常应建立 `dict` 或数据库索引，而不是把数据放进有序列表手写二分。这就是“数据结构服务于操作”的核心。

Python 标准库 `bisect` 提供二分定位，用于维护有序列表；它只负责找到插入位置，不替你处理并发、重复值规则或复杂索引设计。

## 13. 递归、迭代与回溯

### 13.1 递归的三个要素

递归函数调用自己。写递归前必须明确：

1. **基本情况**：何时停止；
2. **递归关系**：如何把大问题变成更小的同类问题；
3. **返回值含义**：每层调用返回什么。

```python
def sum_to(number: int) -> int:
    """计算从 1 到 number 的整数和。

    Args:
        number: 非负整数。

    Returns:
        从 1 累加到 number 的结果。

    Raises:
        ValueError: 当 number 为负数时抛出。
    """
    if number < 0:
        raise ValueError("number 必须是非负整数")
    if number == 0:
        return 0
    return number + sum_to(number - 1)
```

Python 没有尾递归优化，深递归可能触发 `RecursionError`。对大规模线性数据，通常优先用循环；对天然树形的任务，递归仍然清晰有力。

### 13.2 回溯

回溯是“做选择 -> 继续探索 -> 撤销选择 -> 尝试另一种可能”。它常用于全排列、组合、路径搜索和约束满足。回溯问题往往有指数级复杂度，应先明确输入上限，再考虑剪枝。

核心要点不是背模板，而是始终保证：每次 `append()` 的选择，都有对应的 `pop()` 撤销。遗漏撤销会让不同分支共享错误状态。

## 14. 大模型工程中的结构选择

算法学习要落到工程决策。下面是常见映射，但不是机械规则：

| 工程问题 | 优先结构/算法 | 为什么 |
| --- | --- | --- |
| 判断请求是否重复 | `set` / `dict` | 平均 `O(1)` 成员查询 |
| 按 ID 获取文档元数据 | `dict` 或数据库索引 | 键到值的映射 |
| 保留聊天消息顺序 | `list` | 按时间顺序遍历和序列化方便 |
| 高吞吐先进先出缓冲 | `deque` / 专业消息队列 | 队首出队高效，生产环境还需可靠性机制 |
| 解析嵌套 JSON、工具调用 | 栈 / 递归 | 自然匹配嵌套层级 |
| 服务调用链和依赖排查 | 图 + DFS/BFS | 一个服务可依赖多个服务，可能有环 |
| RAG 候选按得分排名 | `sorted()` 或堆 | 根据是否需要完整排序选择 |
| 有序阈值/版本列表定位 | `bisect` / 二分 | 每次排除一半范围 |
| Top K 候选 | `heapq` | 无须把全部候选完整排序 |

例如，下面以 `set` 对输入文档 ID 去重，同时以 `list` 保留首次出现的顺序：

```python
def unique_document_ids(document_ids: list[str]) -> list[str]:
    """去重并保留文档 ID 的首次出现顺序。"""
    seen: set[str] = set()
    result: list[str] = []

    for document_id in document_ids:
        if document_id not in seen:
            seen.add(document_id)
            result.append(document_id)

    return result


print(unique_document_ids(["doc_2", "doc_1", "doc_2", "doc_3"]))
```

只用 `set(document_ids)` 虽然也会去重，但若业务依赖输入顺序，就不应把顺序语义丢掉。选择结构时要同时守住性能与业务含义。

## 15. 典型错误与调试方法

### 15.1 忽略前提条件

- 对无序列表做二分搜索；
- 对有环图做 DFS 却不维护 `visited`；
- 对空列表直接取 `items[0]`；
- 假设哈希键一定存在；
- 假设递归深度永远不会过深。

解决方法：把前提写进函数文档、类型和运行时校验中。对不可信外部输入，类型标注不能替代验证。

### 15.2 为了“快”过早优化

对十条数据使用复杂索引、为一次查询预排序、手写平衡树，可能只增加错误面。先量化：数据量是多少、请求频率是多少、哪个操作真的是热点？

### 15.3 只报复杂度，不说明单位操作

说“这是 `O(n)`”不够。应说明：循环对每个元素做了什么，是否包含隐藏的线性操作。例如在循环中调用 `items.pop(0)`，表面一层循环，但每次弹出又移动元素，总体可能达到 `O(n^2)`。

### 15.4 修改输入导致意外副作用

`list.sort()`、`append()`、`pop()` 都会修改原列表。接口约定需要明确：函数是返回新数据，还是原地修改？调用前后可用断言确认。

```python
values = [3, 1, 2]
original = values.copy()
ranked = sorted(values)

assert values == original
assert ranked == [1, 2, 3]
```

### 15.5 用打印验证而不覆盖边界

至少检查：空输入、单元素、重复值、目标不存在、极端值和非法参数。算法代码最常见错误在边界条件，而不是正常路径。

## 16. 练习：从易到难

每题先写清输入、输出、边界和预期复杂度，再编码。完成后用 `assert` 验证，不要只看一次打印结果。

1. **数组**：实现 `max_score(scores)`，空列表返回 `None`；目标时间 `O(n)`。
2. **哈希表**：输入若干消息，统计每个 `role` 的条数；目标时间 `O(n)`。
3. **集合**：判断一组文档 ID 是否有重复；目标时间平均 `O(n)`。
4. **栈**：检查一段 JSON 风格字符串中 `{}` 和 `[]` 是否正确嵌套。
5. **队列**：模拟最多保留 3 个待处理任务的缓冲区；新任务到达时如何处理溢出？先定义业务规则。
6. **树**：求二叉树最大深度。空树深度为 `0`。
7. **图**：给出服务依赖图，判断从服务 A 是否能到达服务 B；注意处理环。
8. **排序**：对检索结果按 `score` 降序、按 `document_id` 升序作为第二排序键。
9. **搜索**：在升序 token 阈值列表中找到第一个不小于请求值的位置，可研究 `bisect_left`。
10. **综合**：输入文档列表，每条含 `id`、`score`、`tags`。去重、按标签过滤、按分数取前 K 条，并分析每步复杂度。

做题后的复盘模板：

1. 我一开始把数据放在什么结构里，为什么？
2. 核心操作是什么，复杂度是多少？

4. 是否修改了输入？这个副作用是否符合接口预期？

## 19. 下一步

本文建立的是数据结构与算法的地基。下一阶段建议：

1. 在 `pytest` 中为每道已完成练习补上正常、空值、重复值和边界测试；
2. 学习 `collections`、`heapq`、`bisect`、`functools` 等标准库，并在真实小项目中使用；
3. 练习字符串、数组、哈希表、二叉树、图和动态规划的基础题，但每题都先写清前提和复杂度；
4. 将一个 LLM/RAG 小项目中的“聊天历史、缓存、候选排序、任务队列、调用链”逐一标出所用数据结构；
5. 性能出现问题时先用日志和分析工具定位瓶颈，再选择是否替换结构或算法。

真正的掌握，不是看到题目就背模板，而是能解释：数据放在哪里、为什么这样访问、边界如何处理、当规模增长后会发生什么。这个能力会贯穿大模型服务、RAG、Agent、评测管线和线上性能排障。
