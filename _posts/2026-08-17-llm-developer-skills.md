# 大模型开发工程师技能全景指南

大模型开发工程师的核心不是“会调用模型 API”，而是能够把模型能力做成稳定、可评估、可上线、可维护的产品或平台能力。不同岗位的侧重点会不同：应用工程岗位更看重 RAG、Agent、后端与部署；算法和平台岗位则更看重训练、推理优化、GPU 与分布式系统。

本文按能力层次梳理求职时需要掌握的知识、实践能力与面试重点。

## 1. 编程与软件工程基础

这是所有岗位的地基。模型效果再好，如果服务不稳定、无法排障或无法协作交付，也无法构成合格的生产系统。

### Python

- 熟练掌握数据类型、函数、类、异常处理、上下文管理器和类型标注。
- 熟练掌握异步编程（`asyncio`）、协程、线程与进程的适用边界。
- 能处理并发请求、超时、重试、取消、背压与资源释放。
- 能使用 `pytest` 编写单元测试与集成测试，覆盖正常、空值、非法值和边界场景。
- 能使用日志、断点、性能分析工具定位问题。
- 能写出可读、可维护、可测试的服务代码，而不是将业务逻辑堆在单个脚本中。

### 后端、数据与基础设施

- 熟悉 FastAPI 或 Flask，能设计 REST API、流式响应和 WebSocket 服务。
- 理解认证、授权、会话、限流、幂等、超时、重试、CORS 与错误码设计。
- 熟悉 PostgreSQL 或 MySQL 的表设计、索引、事务与查询优化。
- 熟悉 Redis 在缓存、限流、会话、队列和分布式锁中的常见使用方式。
- 具备 Linux、Shell、进程管理、网络排障、环境变量和权限管理基础。
- 熟练使用 Git，包括分支协作、冲突处理、代码审查与可追溯提交。
- 能使用 Docker 容器化服务；理解 CI/CD、配置分环境管理、日志、指标和告警的基本流程。

### 计算机基础

- 数据结构与算法：数组、链表、哈希表、栈队列、树、图、排序、搜索、复杂度分析。
- 网络：HTTP/HTTPS、TCP、DNS、反向代理、长连接、流式传输。
- 操作系统：进程、线程、协程、内存、文件描述符、CPU/GPU 资源竞争。
- 分布式系统基础：服务发现、负载均衡、一致性、缓存一致性、消息队列、故障重试。

## 2. 深度学习与 Transformer 原理

应用开发岗位不一定要求从零训练模型，但应能解释模型运行的关键机制，并据此判断性能、成本和效果问题。

### 数学与机器学习基础

- 线性代数：向量、矩阵乘法、转置、范数、特征值的基本含义。
- 概率统计：条件概率、贝叶斯公式、分布、期望、方差、最大似然估计。
- 微积分与优化：导数、链式法则、梯度下降、学习率、局部最优与收敛。
- 常见损失：交叉熵、均方误差、KL 散度；理解它们分别衡量什么。
- 基本训练概念：训练集、验证集、测试集、过拟合、欠拟合、数据泄漏与泛化。

### PyTorch

- 会使用 `Tensor`、自动求导、`Dataset`、`DataLoader`、`nn.Module` 和优化器。
- 能独立编写小型训练循环，包括训练、验证、保存 checkpoint、恢复训练和记录指标。
- 理解 batch size、学习率、梯度裁剪、梯度累积和混合精度训练的作用。
- 能定位常见问题：数据维度错误、梯度不更新、NaN、OOM、训练不收敛。

### Transformer 与语言模型

- 理解 Token、Tokenizer、BPE/SentencePiece、上下文窗口和 token 成本。
- 理解 Embedding、位置编码、Self-Attention、多头注意力、残差连接、LayerNorm 和 MLP 层。
- 理解 Decoder-only 模型的因果掩码与 next-token prediction 训练目标。
- 能解释 temperature、top-p、top-k、max tokens、stop sequences、重复惩罚对生成结果的影响。
- 了解 GPT、Llama、Qwen、DeepSeek、Mistral、Gemma 等模型的共同架构与选型差异。
- 了解 RoPE、GQA/MQA、MoE、KV Cache、FlashAttention、量化等概念。

面试时应能解释：为什么上下文越长推理越慢、KV Cache 为什么能降低重复计算、MoE 的收益与代价、采样参数为什么影响稳定性。

## 3. 大模型应用开发

这一层解决“怎样可靠地让模型完成业务任务”。重点不是堆砌框架，而是建立可控的输入、输出、状态和失败处理。

### 模型接入与请求治理

- 能接入云端模型 API、本地模型服务或 OpenAI-compatible 接口。
- 实现同步与流式输出，并正确处理连接中断、超时、重试和客户端取消。
- 按用户、模型、业务场景记录 token 用量、延迟、错误率和费用。
- 实现请求限流、并发控制、缓存与降级策略，避免高峰时服务雪崩。
- 管理 API Key、模型配置和多环境密钥，避免敏感信息进入代码库或日志。

### Prompt 与结构化输出

- 能设计系统提示词、角色约束、少样本示例、上下文组织和输出格式。
- 具备 Prompt 版本管理和回归评测意识，而不是靠手工不断改一段文本。
- 使用 JSON Schema、Pydantic 或等价校验机制约束输出字段和类型。
- 对无效 JSON、字段缺失、类型错误和业务不合法结果建立修复或失败路径。
- 理解提示注入、越权指令和上下文污染，并能设计隔离与防护策略。

### Function Calling、工具与 Agent

- 能定义清晰的工具 schema，并在执行前验证模型给出的参数。
- 工具层应有权限校验、超时、重试、审计日志和幂等控制。
- 理解 Agent 的规划、执行、观察、状态保存与终止条件。
- 为多步任务定义状态机、最大轮次、错误处理和人工审批点，避免无限循环或越权执行。
- 能判断何时只需固定工作流，何时才值得使用 Agent；不要为简单流程强行引入多 Agent。

## 4. RAG 与企业知识库

RAG（检索增强生成）是大模型应用岗位的高频考点。目标是从可信知识中检索证据，再让模型据此回答。

### 文档处理与索引

- 处理 PDF、Word、HTML、Markdown、表格和 OCR 文本，识别解析质量问题。
- 清洗乱码、页眉页脚、重复段落、无效空白与错误 OCR 内容。
- 设计元数据：来源、版本、更新时间、文档类型、业务域、用户或组织权限。
- 支持增量同步、文档删除、重建索引与知识版本追踪。
- 设计分块策略：固定长度、标题层级、语义分块和重叠窗口，并理解它们的取舍。

### 检索与重排

- 理解 Embedding、余弦相似度和向量搜索。
- 使用 Milvus、Qdrant、Weaviate、pgvector、Elasticsearch/OpenSearch 中至少一种方案。
- 掌握向量检索、BM25、混合检索、metadata filter 与权限过滤。
- 了解 query rewrite、multi-query、HyDE 等查询增强方法的适用边界。
- 使用 reranker 对候选文档重排，平衡召回数、延迟与成本。
- 控制上下文预算：去重、截断、来源保留、冲突证据处理与重要内容优先。

### RAG 评估与典型问题

- 建立带标准答案、参考证据和难例的测试集。
- 关注检索命中率、Context Precision、Context Recall、答案正确性、忠实性和拒答能力。
- 能定位“答非所问”来自检索、重排、上下文拼接、提示词还是模型本身。
- 处理检索不到、检索无关、知识陈旧、文档冲突、权限泄漏、上下文过长和幻觉。
- 输出可追溯来源，让用户和维护者能够核验回答依据。

## 5. 微调、训练与推理优化

中高级模型、算法或平台岗位通常会考察这部分；应用工程师至少需要理解原理并能完成基础实践。

### 微调与偏好优化

- 理解预训练、监督微调（SFT）、指令微调和领域微调的目标差异。
- 熟悉 LoRA、QLoRA、PEFT 的基本使用、显存优势和适用边界。
- 能设计训练样本格式，完成数据清洗、去重、脱敏、划分训练/验证集。
- 理解模型过拟合、灾难性遗忘、训练数据污染和评测泄漏的风险。
- 了解 RLHF、Reward Model、DPO、ORPO 的基本目标与典型适用场景。
- 熟悉 Hugging Face Transformers、Datasets、PEFT、TRL、Accelerate 等生态工具。

### GPU、量化与推理服务

- 了解显存主要由模型参数、梯度、优化器状态、激活值和 KV Cache 构成。
- 理解 FP32、FP16、BF16、INT8、INT4 的精度、速度和显存取舍。
- 了解 GPTQ、AWQ、GGUF 等量化方案和适配场景。
- 能使用 vLLM、SGLang、TensorRT-LLM 或 llama.cpp 中至少一种推理框架。
- 理解 continuous batching、PagedAttention、prefix caching 对吞吐和延迟的影响。
- 能排查 OOM、GPU 利用率低、首 token 延迟过高、并发下降和长上下文性能问题。
- 了解 DDP、FSDP、ZeRO 等分布式训练概念及其内存优化目标。

## 6. 评估、安全与生产化

生产环境中，大模型系统的价值取决于可衡量的质量和可控的风险，而不是一次演示成功。

### 评估体系

- 定义可量化目标：任务成功率、正确率、忠实性、拒答率、延迟、成本和人工接管率。
- 建立覆盖正常、边界、脏数据、对抗输入和高风险场景的离线评测集。
- 使用规则断言、模型裁判和人工抽检组合评估；对模型裁判本身保持审慎。
- 在模型、Prompt、检索策略或工具发生变化后做回归测试。
- 在线通过用户反馈、A/B 测试、抽样质检和业务指标持续验证。

### 安全与治理

- 防范 Prompt Injection、数据外泄、越权工具调用、提示词泄漏和恶意文件内容。
- 在检索、工具和数据查询层实施用户、租户、角色和文档级权限控制。
- 对敏感数据做最小化传输、脱敏、加密、访问审计和保留周期管理。
- 设计内容安全策略、违规请求处理、拒答说明和人工升级路径。
- 高风险行业还应理解合规要求、数据主权、审计追踪和人工复核边界。

### 可观测性、性能与成本

- 记录 trace id、Prompt 版本、模型版本、检索结果、工具调用、token、耗时和错误原因。
- 关注 TTFT（首 token 时间）、端到端延迟、tokens/s、P95/P99 延迟、并发和 GPU 利用率。
- 使用缓存、模型路由、小模型优先、上下文压缩和批处理控制成本。
- 具备灰度发布、回滚、熔断、降级、监控告警和事故排查意识。

## 7. 面试高频题与答题能力

除了知识点，面试更关心你是否能把需求转为可验证的工程方案。

### 常见题目

- 设计一个支持流式输出、超时、重试、限流和日志的 LLM API 服务。
- 设计企业 RAG：文档如何同步、权限如何过滤、召回率如何提升、幻觉如何治理。
- 给出一个回答不稳定的 Agent，说明如何区分 Prompt、检索、工具、状态机或模型问题。
- 比较 RAG 与微调：知识更新、风格约束、私有数据、成本、时效性和可解释性如何取舍。
- 估算模型显存、并发能力、延迟和部署成本。
- 设计评测集和上线门槛，避免“感觉效果不错”直接发布。
- 说明你如何处理提示注入、工具越权和敏感信息泄露。

### 项目表达框架

每个项目建议能够清楚说明：

1. 业务问题与用户是谁。
2. 输入数据、数据质量和权限边界。
3. 系统架构与关键技术选择。
4. 失败案例与定位过程。
5. 评测方法、量化指标和最终效果。
6. 延迟、吞吐、成本和稳定性优化。
7. 剩余风险、限制条件和下一步改进方向。

不要只描述“用了 LangChain、向量数据库和某个模型”。更有说服力的是说明为什么选择它们、替代方案是什么、数据和指标如何证明方案有效。

## 8. 推荐学习路径

### 第一阶段：工程与模型基础

- 完成 Python、FastAPI、SQL、Redis、Docker、Git 与测试基础。
- 使用 PyTorch 复现一个简单分类或文本生成训练流程。
- 学习 Transformer、Tokenizer、Attention、采样参数和 KV Cache。

### 第二阶段：可用的大模型应用

- 完成一个支持流式输出、结构化结果和工具调用的 LLM 服务。
- 为模型输出建立 Schema 校验、异常处理、日志和自动化测试。
- 学习 Prompt 版本管理与基础离线评测。

### 第三阶段：RAG 闭环

- 从文档解析、分块、向量化、检索、重排做到答案引用。
- 加入权限过滤、增量更新、失败分析和测试集。
- 用量化指标优化检索质量、答案忠实性、延迟和成本。

### 第四阶段：部署与优化

- 使用 Docker 部署服务，补全监控、限流、缓存和灰度策略。
- 尝试本地模型、vLLM 或等价推理服务。
- 学习量化、批处理、上下文管理和 GPU OOM 排障。

### 第五阶段：进阶方向

- 根据目标岗位选择深入微调、分布式训练、Agent、多模态、语音或模型平台。
- 构建能复现的评测和实验记录，形成可用于面试展示的项目资产。

## 9. 最值得准备的作品集项目

相比普通聊天机器人，更推荐完成一个小而完整、可被验证的项目：

- 企业知识库助手：含文档解析、混合检索、重排、引用、权限过滤、增量更新和评测集。
- 智能业务工作流：含结构化输出、工具调用、审批节点、审计日志和失败恢复。
- 本地模型推理服务：含量化、流式接口、并发测试、性能指标和成本比较。
- 某个垂直领域助手：展示真实的数据治理、风险约束、效果评测和业务指标。

一个有竞争力的项目应至少有可运行代码、架构说明、测试数据、评测结果、失败案例，以及对延迟和成本的说明。这样才能证明你不仅“会调模型”，还具备把大模型能力稳定交付到实际业务中的工程能力。
