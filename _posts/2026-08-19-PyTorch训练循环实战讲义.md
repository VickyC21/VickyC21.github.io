# PyTorch 小型训练循环实战讲义：训练、验证、Checkpoint 与恢复训练

> 目标：能够独立训练一个小型分类模型，在验证集上判断是否变好，记录指标，在中断后继续训练，并保存表现最佳的版本。

训练循环不是“让模型自己学习”的黑箱。它由一段可重复、可检查的步骤组成：取一批样本，模型预测，计算误差，反向传播，更新参数。一个合格的工程训练循环还要包含验证、指标和 checkpoint，否则你无法判断模型是否泛化，也无法可靠地继续实验。

## 1. 先记住四个概念

| 名称 | 含义 |
|---|---|
| batch | 一小批样本，例如 64 条 |
| step | 处理一个 batch 并更新一次参数 |
| epoch | 训练集被完整遍历一次 |
| loss | 衡量预测与正确标签差距的数值，通常越小越好 |

训练的核心五行代码如下：

~~~python
optimizer.zero_grad()
logits = model(features)
loss = criterion(logits, labels)
loss.backward()
optimizer.step()
~~~

其中：

- zero_grad() 清空上个 batch 的梯度。PyTorch 默认累积梯度，不会自动覆盖。
- model(features) 是前向计算，得到 logits，即每个类别的原始分数。
- criterion 比较 logits 和标签，生成一个标量损失。
- backward() 计算参数梯度，但不修改参数。
- step() 才读取梯度并真正修改模型参数。

## 2. 为什么要分训练集、验证集和测试集

训练集用于更新参数；验证集只用于衡量泛化、调学习率和选择最佳版本；测试集应该在方案确定后才使用。若反复根据测试集结果调整模型，测试数据已参与决策，最终得分会虚高，这叫数据泄漏。

训练 loader 应设 shuffle=True，让每轮的局部顺序不同；验证 loader 不更新模型，因此可设 shuffle=False。

## 3. 一份可运行的完整示例

将下面内容保存为 train.py，安装 torch 后运行 python train.py。示例生成带噪声的二维二分类数据，因此不依赖外部下载。

~~~python
"""演示可恢复的小型 PyTorch 分类训练循环。"""

from __future__ import annotations

import csv
from pathlib import Path
from typing import Any

import torch
from torch import Tensor, nn
from torch.optim import Adam
from torch.utils.data import DataLoader, TensorDataset


BATCH_SIZE = 64
LEARNING_RATE = 1e-2
EPOCHS = 30
LAST_PATH = Path("checkpoints/last.pt")
BEST_PATH = Path("checkpoints/best.pt")
METRICS_PATH = Path("metrics.csv")


def make_data() -> tuple[Tensor, Tensor]:
    """生成可用于演示的二维二分类数据。

    Returns:
        特征张量和 long 类型的类别编号标签。
    """
    torch.manual_seed(42)
    first = torch.randn(1_000, 2) + torch.tensor([-1.0, -1.0])
    second = torch.randn(1_000, 2) + torch.tensor([1.0, 1.0])
    features = torch.cat((first, second))
    labels = torch.cat(
        (
            torch.zeros(1_000, dtype=torch.long),
            torch.ones(1_000, dtype=torch.long),
        )
    )
    return features, labels


def make_loaders() -> tuple[DataLoader, DataLoader]:
    """划分训练/验证集并构造 DataLoader。

    Returns:
        打乱的训练 loader 和不打乱的验证 loader。
    """
    features, labels = make_data()
    indices = torch.randperm(len(features))
    split = int(len(features) * 0.8)
    train_indices = indices[:split]
    valid_indices = indices[split:]

    train_set = TensorDataset(features[train_indices], labels[train_indices])
    valid_set = TensorDataset(features[valid_indices], labels[valid_indices])
    return (
        DataLoader(train_set, batch_size=BATCH_SIZE, shuffle=True),
        DataLoader(valid_set, batch_size=BATCH_SIZE, shuffle=False),
    )


class Classifier(nn.Module):
    """一个用于二维二分类的最小多层感知机。"""

    def __init__(self) -> None:
        super().__init__()
        self.layers = nn.Sequential(
            nn.Linear(2, 16),
            nn.ReLU(),
            nn.Linear(16, 2),
        )

    def forward(self, features: Tensor) -> Tensor:
        """计算两个类别的 logits。

        Args:
            features: 形状为 [batch_size, 2] 的浮点特征。

        Returns:
            形状为 [batch_size, 2] 的原始类别分数。
        """
        return self.layers(features)


def train_one_epoch(
    model: nn.Module,
    loader: DataLoader,
    criterion: nn.Module,
    optimizer: torch.optim.Optimizer,
    device: torch.device,
) -> tuple[float, float]:
    """训练一个 epoch 并返回平均损失和准确率。"""
    model.train()
    total_loss = 0.0
    correct = 0
    count = 0

    for features, labels in loader:
        features = features.to(device)
        labels = labels.to(device)

        optimizer.zero_grad()
        logits = model(features)
        loss = criterion(logits, labels)
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
        optimizer.step()

        batch_size = labels.size(0)
        total_loss += loss.item() * batch_size
        correct += (logits.argmax(dim=1) == labels).sum().item()
        count += batch_size

    return total_loss / count, correct / count


@torch.inference_mode()
def evaluate(
    model: nn.Module,
    loader: DataLoader,
    criterion: nn.Module,
    device: torch.device,
) -> tuple[float, float]:
    """在验证集计算平均损失和准确率，不生成梯度。"""
    model.eval()
    total_loss = 0.0
    correct = 0
    count = 0

    for features, labels in loader:
        features = features.to(device)
        labels = labels.to(device)
        logits = model(features)
        loss = criterion(logits, labels)

        batch_size = labels.size(0)
        total_loss += loss.item() * batch_size
        correct += (logits.argmax(dim=1) == labels).sum().item()
        count += batch_size

    return total_loss / count, correct / count


### 3.1 继续补全 checkpoint、指标与主循环

将以下代码接在上一个代码块之后，和前面的函数构成同一个 train.py：

~~~python
def save_checkpoint(
    path: Path,
    epoch: int,
    model: nn.Module,
    optimizer: torch.optim.Optimizer,
    best_valid_loss: float,
) -> None:
    """保存恢复训练所需的状态。

    Args:
        path: checkpoint 文件路径。
        epoch: 已完成的 epoch 编号。
        model: 当前模型。
        optimizer: 当前优化器，Adam 的动量状态也要保存。
        best_valid_loss: 当前最小验证损失。
    """
    path.parent.mkdir(parents=True, exist_ok=True)
    torch.save(
        {
            "epoch": epoch,
            "model_state_dict": model.state_dict(),
            "optimizer_state_dict": optimizer.state_dict(),
            "best_valid_loss": best_valid_loss,
        },
        path,
    )


def load_checkpoint(
    path: Path,
    model: nn.Module,
    optimizer: torch.optim.Optimizer,
    device: torch.device,
) -> tuple[int, float]:
    """加载模型、优化器和训练进度。

    Args:
        path: 已存在的 checkpoint 路径。
        model: 与保存时结构一致的模型实例。
        optimizer: 与保存时兼容的优化器实例。
        device: 当前训练设备。

    Returns:
        下一个应开始的 epoch 与历史最佳验证损失。
    """
    checkpoint: dict[str, Any] = torch.load(
        path,
        map_location=device,
        weights_only=True,
    )
    model.load_state_dict(checkpoint["model_state_dict"])
    optimizer.load_state_dict(checkpoint["optimizer_state_dict"])
    return int(checkpoint["epoch"]) + 1, float(checkpoint["best_valid_loss"])


def append_metrics(
    epoch: int,
    train_loss: float,
    train_accuracy: float,
    valid_loss: float,
    valid_accuracy: float,
) -> None:
    """将一个 epoch 的指标追加到 UTF-8 CSV 文件。"""
    need_header = not METRICS_PATH.exists()
    with METRICS_PATH.open("a", newline="", encoding="utf-8") as file:
        writer = csv.writer(file)
        if need_header:
            writer.writerow(
                [
                    "epoch",
                    "train_loss",
                    "train_accuracy",
                    "valid_loss",
                    "valid_accuracy",
                ]
            )
        writer.writerow(
            [
                epoch,
                f"{train_loss:.6f}",
                f"{train_accuracy:.6f}",
                f"{valid_loss:.6f}",
                f"{valid_accuracy:.6f}",
            ]
        )


def main() -> None:
    """执行训练、验证、指标记录和断点恢复。"""
    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    print(f"使用设备: {device}")

    train_loader, valid_loader = make_loaders()
    model = Classifier().to(device)
    criterion = nn.CrossEntropyLoss()
    optimizer = Adam(model.parameters(), lr=LEARNING_RATE)

    start_epoch = 1
    best_valid_loss = float("inf")
    if LAST_PATH.exists():
        start_epoch, best_valid_loss = load_checkpoint(
            LAST_PATH,
            model,
            optimizer,
            device,
        )
        print(f"已恢复 checkpoint，将从 epoch {start_epoch} 开始。")

    for epoch in range(start_epoch, EPOCHS + 1):
        train_loss, train_accuracy = train_one_epoch(
            model,
            train_loader,
            criterion,
            optimizer,
            device,
        )
        valid_loss, valid_accuracy = evaluate(
            model,
            valid_loader,
            criterion,
            device,
        )
        append_metrics(
            epoch,
            train_loss,
            train_accuracy,
            valid_loss,
            valid_accuracy,
        )

        is_best = valid_loss < best_valid_loss
        if is_best:
            best_valid_loss = valid_loss

        save_checkpoint(
            LAST_PATH,
            epoch,
            model,
            optimizer,
            best_valid_loss,
        )
        if is_best:
            save_checkpoint(
                BEST_PATH,
                epoch,
                model,
                optimizer,
                best_valid_loss,
            )

        print(
            f"epoch={epoch:02d} "
            f"train_loss={train_loss:.4f} train_acc={train_accuracy:.2%} "
            f"valid_loss={valid_loss:.4f} valid_acc={valid_accuracy:.2%}"
        )


if __name__ == "__main__":
    main()
~~~

再次运行脚本时，如果 last.pt 已经存在，程序会先恢复模型参数、优化器内部状态、最佳验证损失和下一个 epoch，再继续训练。第一次运行请确保 EPOCHS 足够大；若训练已经完成到 EPOCHS，第二次运行不会继续，这是预期行为。想重新从头训练时，删除 checkpoints 目录和 metrics.csv。

## 4. 必须读懂的细节

### 4.1 CrossEntropyLoss 的形状契约

本例中的输入形状必须满足：

~~~text
logits: [batch_size, class_count]，浮点型
labels: [batch_size]，torch.long，值域是 0 到 class_count - 1
~~~

二分类 batch 为 64 时，logits 的形状是 [64, 2]，labels 的形状是 [64]。不要为本例的标签手工做 one-hot。模型末尾也不要再加 Softmax，因为 CrossEntropyLoss 在内部已经以数值稳定的方式完成这一步。

预测类别直接使用：

~~~python
predictions = logits.argmax(dim=1)
~~~

只有需要向用户显示概率时，才计算 torch.softmax(logits, dim=1)。

### 4.2 为什么训练和验证都要切换模式

model.train() 与 model.eval() 会影响 Dropout 与 BatchNorm。Dropout 训练时有随机性、验证时关闭；BatchNorm 训练时更新统计量、验证时使用已学统计量。即使当前模型没有这些层，也要养成训练先 train、验证先 eval 的固定习惯。

验证函数使用 inference_mode() 关闭自动求导，以减少内存和计算。它与 eval() 职责不同：inference_mode 不改变 Dropout/BatchNorm 行为，eval 不关闭梯度；验证时通常两者都需要。

### 4.3 为什么平均 loss 要按样本数加权

CrossEntropyLoss 默认返回当前 batch 的平均损失。最后一个 batch 可能比其他 batch 小，因此不要直接对“每批 loss”再平均。正确计算是：

~~~python
total_loss += loss.item() * batch_size
sample_count += batch_size
epoch_loss = total_loss / sample_count
~~~

记录 loss 时务必使用 loss.item()。把带计算图的 loss tensor 连续存入列表，会让显存难以释放。

## 5. Checkpoint 应保存什么

只保存 model.state_dict() 足以推理，但不足以严格恢复训练。Adam 会维护内部动量状态；不加载 optimizer_state_dict 时，模型虽然从旧权重开始，优化过程却从新的状态开始。

| 目标 | 至少保存的状态 |
|---|---|
| 仅推理 | 模型权重 |
| 恢复训练 | 模型权重、优化器状态、epoch、最佳指标 |
| 严格复现 | 前述状态，加随机数状态、调度器、配置和数据版本 |

推荐保存 state_dict，而不是直接保存整个模型对象。前者更不依赖 Python 的类路径和文件结构。

last.pt 与 best.pt 的职责不能混淆：

- last.pt 是最近成功完成的位置，用于机器重启、程序崩溃或手动暂停后的继续。
- best.pt 是验证集最好的版本，用于最终测试、导出和部署。

恢复训练前还必须确认模型结构、优化器、输入预处理、特征列顺序、标签映射和数据版本都没有改变。

## 6. 指标与实验记录

metrics.csv 类似这样：

~~~csv
epoch,train_loss,train_accuracy,valid_loss,valid_accuracy
1,0.513412,0.760625,0.382017,0.842500
2,0.304526,0.873125,0.258967,0.907500
~~~

每次只调整一个变量，例如只修改学习率或 batch size，然后比较验证曲线。不要因为某一轮训练准确率最高就认定更好，模型选择优先看验证集。

| 现象 | 常见原因 | 先做什么 |
|---|---|---|
| 训练和验证损失都高 | 欠拟合、数据/标签错误、学习率不合适 | 做小 batch 过拟合实验 |
| 训练损失降而验证损失升 | 过拟合 | 保存 best、早停、更多数据或正则化 |
| loss 为 NaN | 学习率过大、输入有 NaN/Inf | 检查数据、降低学习率 |
| 准确率接近随机 | 标签错位、输出维度错、未更新参数 | 打印 shape、梯度和参数 |
| 每轮完全相同 | 忘记 step、学习率极小、数据错误 | 检查训练五步 |

## 7. 排错利器：过拟合一个小 batch

若模型不收敛，不要立刻大范围调参。先固定 16 个样本并重复训练，模型应该能把它们几乎完全记住：

~~~python
tiny_features, tiny_labels = next(iter(train_loader))
tiny_features = tiny_features[:16].to(device)
tiny_labels = tiny_labels[:16].to(device)

for _ in range(300):
    optimizer.zero_grad()
    logits = model(tiny_features)
    loss = criterion(logits, tiny_labels)
    loss.backward()
    optimizer.step()
~~~

如果这个实验失败，请逐项检查：输入是否与标签一一对应、标签范围是否合法、输出类别数是否正确、是否调用了 backward 和 step、是否误用 inference_mode、参数是否被冻结、学习率是否极端。

小 batch 过拟合只能证明训练管线连通，不能证明泛化好。

## 8. 梯度裁剪、累积和混合精度

梯度裁剪用于抑制过大的梯度，位置必须在 backward 后、step 前：

~~~python
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
~~~

显存装不下大 batch 时，可做梯度累积。关键是损失除以累计次数，否则梯度会被放大：

~~~python
accumulation_steps = 4
optimizer.zero_grad()

for step, (features, labels) in enumerate(train_loader, start=1):
    logits = model(features)
    loss = criterion(logits, labels) / accumulation_steps
    loss.backward()

    if step % accumulation_steps == 0:
        optimizer.step()
        optimizer.zero_grad()
~~~

GPU 上确认 FP32 逻辑正确后再启用混合精度。启用 GradScaler 后，也应把 scaler.state_dict 放进 checkpoint。

## 9. 常见故障与练习

- 设备不一致：model、features、labels 必须在同一个 device；加载 checkpoint 时使用 map_location。
- OOM：先减小 batch size，再减小输入尺寸或序列长度；不要保存带计算图的 tensor；随后才尝试梯度累积或混合精度。
- 维度错：临时打印 features.shape、labels.shape、logits.shape；不要随意 squeeze，batch size 为 1 时可能误删 batch 维度。
- 梯度为 None：检查训练代码是否处于 no_grad/inference_mode，loss 是否依赖模型输出。

建议按顺序练习：原样运行并观察 CSV；中途 Ctrl+C 后恢复；故意删除 optimizer.step 观察停滞；对比学习率 1、1e-5、1e-2；改变隐藏层宽度；再替换成自己的 CSV、图像或文本小数据。

当你能独立解释 zero_grad、backward、step、eval、inference_mode、last.pt 与 best.pt 的作用，并能用小 batch 过拟合定位问题时，就具备了学习 LoRA 微调、语言模型训练和分布式训练的可靠基础。
