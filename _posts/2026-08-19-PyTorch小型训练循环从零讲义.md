# PyTorch 小型训练循环：从训练到断点恢复的零基础讲义

这篇讲义对应大模型开发工程师需要具备的一项基础能力：**能独立编写一个小型训练循环，完成训练、验证、保存 checkpoint、恢复训练和记录指标。**

目标不是背下一段模板代码，而是能回答下面五个问题：

1. 一批数据进入模型后，参数究竟在什么时候被更新？
2. 为什么验证阶段必须与训练阶段分开？
3. checkpoint 中为什么不能只保存模型权重？
4. 程序中断后，怎样从正确的位置继续，而不是重新训练或丢失最优结果？
5. 如何用指标判断训练是在变好、过拟合，还是已经出了问题？

本文假定你已了解 Python 的函数、循环和类，刚开始接触 PyTorch。示例使用一个人工生成的二维二分类数据集，因此不需要下载数据；你可以先跑通完整流程，再将数据和模型替换为图像、文本或真实业务数据。

## 1. 学习目标与边界

完成本文后，你应当能够：

- 解释 `Dataset`、`DataLoader`、`nn.Module`、损失函数和优化器分别负责什么；
- 写出正确的单批训练步骤：前向传播、计算损失、清空梯度、反向传播、更新参数；
- 在验证阶段正确使用 `model.eval()` 与 `torch.no_grad()`；
- 按 epoch 保存 `last.pt`，并按验证指标保存 `best.pt`；
- 恢复模型、优化器、学习率调度器、已完成 epoch 和最优指标；
- 将每轮指标追加写入 `metrics.jsonl`，并据此定位常见训练问题。

本文不讨论分布式训练、混合精度、断点到“某一个 batch”的精确恢复、TensorBoard/W&B 云端追踪和大模型微调。这些建立在本讲的单机训练闭环之上。

## 2. 先建立全景：一个训练实验有哪些状态

把训练看成一个反复执行的实验循环，而不是“调用一次 `fit`”。一次完整实验至少有以下对象：

| 对象 | 职责 | 是否必须进入 checkpoint |
| --- | --- | --- |
| 数据集与 DataLoader | 提供按批次组织的数据 | 通常不保存；应保存数据版本、随机种子和划分规则 |
| 模型 | 根据输入给出预测 | 必须保存 `model.state_dict()` |
| 损失函数 | 衡量预测与真实标签的差距 | 通常无状态，不需要保存 |
| 优化器 | 根据梯度更新模型参数 | 必须保存 `optimizer.state_dict()` |
| 学习率调度器 | 随训练进度改变学习率 | 使用时必须保存其状态 |
| epoch 和最优指标 | 说明训练到哪里、什么结果最好 | 必须保存 |
| 指标日志 | 记录损失、准确率、学习率等 | 推荐独立持久化，便于分析 |

训练循环的核心数据流如下：

```text
训练数据 -> 模型(train mode) -> logits -> loss
                                   |
                              backward()
                                   |
优化器根据梯度更新参数 <- optimizer.step()

验证数据 -> 模型(eval mode) -> logits -> 指标
                                   |
                           不计算梯度，不更新参数
```

其中 **epoch（轮）** 表示完整遍历一次训练集；**batch（批）** 表示一次送入模型的一小组样本。若训练集有 1,000 个样本、`batch_size=64`，一个 epoch 大约有 16 个 batch。

## 3. 环境与第一个最小闭环

建议使用独立的虚拟环境。以下命令安装 CPU 版 PyTorch；若你已有 CUDA 环境，请以 [PyTorch 官网安装页](https://pytorch.org/get-started/locally/) 给出的命令为准。

```bash
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install torch
```

先理解一个 batch 的最小训练步骤：

```python
# x 的形状为 [batch_size, 特征数]，y 的形状为 [batch_size]
logits = model(x)                 # 1. 前向传播，得到未归一化分类分数
loss = criterion(logits, y)       # 2. 计算预测与标签的差距

optimizer.zero_grad()             # 3. 清空上一批残留的梯度
loss.backward()                   # 4. 反向传播，计算每个参数的梯度
optimizer.step()                  # 5. 用梯度更新参数
```

这五行的顺序不能随意交换：

- PyTorch 默认会**累加**梯度，所以通常在每个 batch 反向传播前调用 `zero_grad()`；
- `backward()` 只负责计算梯度，不会修改参数；
- 真正修改模型参数的是 `optimizer.step()`；
- 训练时不要把 `loss.item()` 再传给 `backward()`：`item()` 会把 Tensor 转成普通 Python 数字，计算图已经断开。

## 4. 关键概念：logits、损失、预测与准确率

以二分类为例，模型最后输出两个数字，例如 `[2.4, -0.8]`。它们叫 **logits**，表示两个类别的相对倾向，不是概率。

```python
logits = torch.tensor([[2.4, -0.8]])
predicted_class = logits.argmax(dim=1)  # 得到类别索引 0
probabilities = torch.softmax(logits, dim=1)  # 如需概率再做 softmax
```

`nn.CrossEntropyLoss()` 接收的输入是 logits 和类别索引，内部已经完成数值稳定的 softmax 与对数计算。因此：

- 输出层不要额外加 `Softmax`；
- 标签应该是整数类别索引，例如 `torch.tensor([0, 1, 0])`；
- 标签 dtype 对 `CrossEntropyLoss` 必须是 `torch.long`；
- 分类预测通常用 `logits.argmax(dim=1)`。

损失（loss）是优化目标，越小通常说明模型在当前数据上拟合得更好；准确率（accuracy）是可读性更强的业务指标。两者都应观察：类别不均衡时，准确率可能看起来很高却没有实际价值，此时还应看 precision、recall、F1 或混淆矩阵。

## 5. 完整可运行示例

将下面代码保存为 `train_toy_classifier.py` 后运行。它使用两个高斯分布模拟两类样本，并包含以下完整能力：

- 固定随机种子；
- 训练/验证集划分；
- 多层感知机分类器；
- 训练与验证函数；
- `last.pt` 和 `best.pt` checkpoint；
- `--resume` 恢复训练；
- 每个 epoch 追加一条 JSONL 指标记录；
- 原子替换 checkpoint 文件，避免半写入文件覆盖旧结果。

```python
"""演示一个具备训练、验证、断点恢复和指标记录能力的最小 PyTorch 训练脚本。"""

from __future__ import annotations

import argparse
import json
import random
from pathlib import Path
from typing import Any

import torch
from torch import Tensor, nn
from torch.optim import AdamW, Optimizer
from torch.optim.lr_scheduler import ReduceLROnPlateau
from torch.utils.data import DataLoader, Dataset, random_split


class ToyBinaryDataset(Dataset[tuple[Tensor, Tensor]]):
    """生成线性不可完全分离的二维二分类玩具数据。

    两个类别分别围绕不同中心采样。数据虽简单，但足以观察损失下降、验证指标、
    checkpoint 保存与恢复等训练循环行为。

    Args:
        samples_per_class: 每个类别生成的样本数量。
        seed: 控制数据生成过程的随机种子。
    """

    def __init__(self, samples_per_class: int, seed: int) -> None:
        generator = torch.Generator().manual_seed(seed)
        negative = torch.randn(samples_per_class, 2, generator=generator) + torch.tensor([-1.5, -1.0])
        positive = torch.randn(samples_per_class, 2, generator=generator) + torch.tensor([1.5, 1.0])

        self.features = torch.cat([negative, positive], dim=0)
        self.labels = torch.cat(
            [
                torch.zeros(samples_per_class, dtype=torch.long),
                torch.ones(samples_per_class, dtype=torch.long),
            ]
        )

    def __len__(self) -> int:
        """返回数据集中的样本总数。"""
        return len(self.labels)

    def __getitem__(self, index: int) -> tuple[Tensor, Tensor]:
        """返回指定位置的一条特征和标签。"""
        return self.features[index], self.labels[index]


class Classifier(nn.Module):
    """一个用于二维输入、二分类输出的小型全连接网络。"""

    def __init__(self) -> None:
        super().__init__()
        self.layers = nn.Sequential(
            nn.Linear(2, 16),
            nn.ReLU(),
            nn.Linear(16, 2),
        )

    def forward(self, features: Tensor) -> Tensor:
        """根据一个 batch 的二维特征返回两个类别的 logits。

        Args:
            features: 形状为 `[batch_size, 2]` 的浮点特征。

        Returns:
            形状为 `[batch_size, 2]` 的未归一化分类分数。
        """
        return self.layers(features)


def set_seed(seed: int) -> None:
    """固定本示例涉及的随机源，提升实验可复现性。

    Args:
        seed: 要使用的随机种子。
    """
    random.seed(seed)
    torch.manual_seed(seed)


def run_epoch(
    model: nn.Module,
    loader: DataLoader[tuple[Tensor, Tensor]],
    criterion: nn.Module,
    device: torch.device,
    optimizer: Optimizer | None = None,
) -> dict[str, float]:
    """运行完整的一轮训练或验证并按样本数汇总指标。

    当 `optimizer` 存在时，此函数执行训练并更新参数；当它为 `None` 时，函数
    只做验证。使用样本数加权而非简单平均 batch loss，可避免最后一个不完整 batch
    造成统计偏差。

    Args:
        model: 要训练或验证的模型。
        loader: 提供一个数据集切分的批数据加载器。
        criterion: 计算分类损失的函数。
        device: 模型与数据所在的 CPU 或 GPU 设备。
        optimizer: 训练时使用的优化器；验证时传入 `None`。

    Returns:
        含有 `loss` 和 `accuracy` 的字典。
    """
    is_training = optimizer is not None
    model.train(is_training)

    total_loss = 0.0
    total_correct = 0
    total_samples = 0

    # 验证阶段关闭梯度跟踪，减少显存占用并避免无意构建计算图。
    with torch.set_grad_enabled(is_training):
        for features, labels in loader:
            features = features.to(device)
            labels = labels.to(device)

            logits = model(features)
            loss = criterion(logits, labels)

            if is_training:
                optimizer.zero_grad()
                loss.backward()
                optimizer.step()

            batch_size = labels.size(0)
            total_loss += loss.item() * batch_size
            total_correct += (logits.argmax(dim=1) == labels).sum().item()
            total_samples += batch_size

    if total_samples == 0:
        raise ValueError("DataLoader 没有提供任何样本，无法计算指标。")

    return {
        "loss": total_loss / total_samples,
        "accuracy": total_correct / total_samples,
    }


def save_checkpoint(
    path: Path,
    model: nn.Module,
    optimizer: Optimizer,
    scheduler: ReduceLROnPlateau,
    completed_epoch: int,
    best_val_accuracy: float,
) -> None:
    """把恢复训练所需状态写入 checkpoint，并以替换方式完成落盘。

    Args:
        path: checkpoint 的目标文件路径。
        model: 当前模型。
        optimizer: 当前优化器。
        scheduler: 当前学习率调度器。
        completed_epoch: 已完成的 epoch 数，恢复后从该值继续。
        best_val_accuracy: 截至当前最好的验证准确率。
    """
    checkpoint: dict[str, Any] = {
        "epoch": completed_epoch,
        "model_state": model.state_dict(),
        "optimizer_state": optimizer.state_dict(),
        "scheduler_state": scheduler.state_dict(),
        "best_val_accuracy": best_val_accuracy,
    }
    path.parent.mkdir(parents=True, exist_ok=True)

    # 先写入同目录临时文件，再替换目标文件，降低中断时损坏旧 checkpoint 的概率。
    temporary_path = path.with_suffix(".tmp")
    torch.save(checkpoint, temporary_path)
    temporary_path.replace(path)


def load_checkpoint(
    path: Path,
    model: nn.Module,
    optimizer: Optimizer,
    scheduler: ReduceLROnPlateau,
    device: torch.device,
) -> tuple[int, float]:
    """从 checkpoint 恢复训练状态。

    Args:
        path: 已存在的 checkpoint 文件路径。
        model: 待恢复参数的模型。
        optimizer: 待恢复内部状态的优化器。
        scheduler: 待恢复进度的学习率调度器。
        device: 当前运行设备，用于安全映射保存时的 Tensor。

    Returns:
        包含“已完成 epoch 数”和“当前最佳验证准确率”的元组。

    Raises:
        FileNotFoundError: 指定 checkpoint 不存在时抛出。
        KeyError: checkpoint 缺少必要字段时抛出。
    """
    checkpoint = torch.load(path, map_location=device)
    model.load_state_dict(checkpoint["model_state"])
    optimizer.load_state_dict(checkpoint["optimizer_state"])
    scheduler.load_state_dict(checkpoint["scheduler_state"])
    return int(checkpoint["epoch"]), float(checkpoint["best_val_accuracy"])


def append_metrics(path: Path, record: dict[str, float | int]) -> None:
    """向 JSONL 文件追加一条可独立解析的训练指标记录。

    Args:
        path: 指标文件路径。
        record: 当前 epoch 的指标和元数据。
    """
    path.parent.mkdir(parents=True, exist_ok=True)
    with path.open("a", encoding="utf-8") as metrics_file:
        metrics_file.write(json.dumps(record, ensure_ascii=False) + "\n")


def parse_args() -> argparse.Namespace:
    """解析命令行参数并返回训练配置。"""
    parser = argparse.ArgumentParser(description="运行一个小型 PyTorch 二分类训练实验。")
    parser.add_argument("--epochs", type=int, default=20, help="总共要完成的训练轮数。")
    parser.add_argument("--batch-size", type=int, default=64, help="每个 batch 的样本数。")
    parser.add_argument("--learning-rate", type=float, default=1e-2, help="初始学习率。")
    parser.add_argument("--output-dir", type=Path, default=Path("runs/toy_classifier"), help="实验输出目录。")
    parser.add_argument("--resume", action="store_true", help="从输出目录中的 last.pt 恢复训练。")
    return parser.parse_args()


def main() -> None:
    """准备数据与训练对象，运行训练闭环并输出每轮结果。"""
    args = parse_args()
    set_seed(42)

    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    dataset = ToyBinaryDataset(samples_per_class=500, seed=42)
    train_size = int(len(dataset) * 0.8)
    train_dataset, val_dataset = random_split(
        dataset,
        [train_size, len(dataset) - train_size],
        generator=torch.Generator().manual_seed(42),
    )
    train_loader = DataLoader(train_dataset, batch_size=args.batch_size, shuffle=True)
    val_loader = DataLoader(val_dataset, batch_size=args.batch_size, shuffle=False)

    model = Classifier().to(device)
    criterion = nn.CrossEntropyLoss()
    optimizer = AdamW(model.parameters(), lr=args.learning_rate, weight_decay=1e-4)
    scheduler = ReduceLROnPlateau(optimizer, mode="min", factor=0.5, patience=3)

    last_checkpoint = args.output_dir / "last.pt"
    best_checkpoint = args.output_dir / "best.pt"
    metrics_path = args.output_dir / "metrics.jsonl"
    start_epoch = 0
    best_val_accuracy = float("-inf")

    if args.resume:
        start_epoch, best_val_accuracy = load_checkpoint(
            last_checkpoint,
            model,
            optimizer,
            scheduler,
            device,
        )
        print(f"已恢复：将从第 {start_epoch + 1} 个 epoch 开始训练。")

    for epoch in range(start_epoch, args.epochs):
        train_metrics = run_epoch(model, train_loader, criterion, device, optimizer)
        val_metrics = run_epoch(model, val_loader, criterion, device)
        scheduler.step(val_metrics["loss"])

        current_lr = optimizer.param_groups[0]["lr"]
        record: dict[str, float | int] = {
            "epoch": epoch + 1,
            "train_loss": train_metrics["loss"],
            "train_accuracy": train_metrics["accuracy"],
            "val_loss": val_metrics["loss"],
            "val_accuracy": val_metrics["accuracy"],
            "learning_rate": current_lr,
        }
        append_metrics(metrics_path, record)

        # last.pt 用于恢复“最新进度”；best.pt 用于最终推理或交付最佳模型。
        if val_metrics["accuracy"] > best_val_accuracy:
            best_val_accuracy = val_metrics["accuracy"]
            save_checkpoint(best_checkpoint, model, optimizer, scheduler, epoch + 1, best_val_accuracy)

        save_checkpoint(last_checkpoint, model, optimizer, scheduler, epoch + 1, best_val_accuracy)
        print(
            f"epoch={epoch + 1:02d} "
            f"train_loss={train_metrics['loss']:.4f} "
            f"val_loss={val_metrics['loss']:.4f} "
            f"val_acc={val_metrics['accuracy']:.3f} "
            f"lr={current_lr:.5f}"
        )


if __name__ == "__main__":
    main()
```

运行一次完整训练：

```bash
python train_toy_classifier.py --epochs 20 --output-dir runs/toy_classifier
```

模拟在 8 轮后中断并恢复：

```bash
python train_toy_classifier.py --epochs 8 --output-dir runs/toy_classifier
python train_toy_classifier.py --epochs 20 --output-dir runs/toy_classifier --resume
```

第二条命令不会从 epoch 1 开始，而会读取 `runs/toy_classifier/last.pt`，从第 9 个 epoch 继续到第 20 个。注意：指标文件会继续追加记录；如果你想做一次完全独立的新实验，请换一个 `--output-dir`，不要复用旧目录。

## 6. 逐段理解完整脚本

### 6.1 为什么数据要分为训练集和验证集

训练集参与参数更新，模型会直接“看见”它；验证集只用于评估泛化能力，不能参与反向传播和选参。若用同一份数据同时训练和报告效果，模型可能只是记住了数据，数字会过于乐观。

本例用 `random_split` 做了 80%/20% 划分，并使用固定生成器保证划分稳定。真实项目还需要额外保留**测试集**：

- 训练集：更新参数；
- 验证集：决定早停、最佳模型、学习率等训练决策；
- 测试集：在所有决策完成后，做一次最终、尽量无偏的报告。

文本、时间序列和同一用户多条记录的数据不能机械随机切分。例如，未来数据不能进入时间序列的训练集；同一用户的数据通常应放在同一切分中，防止数据泄漏。

### 6.2 `model.train()` 和 `model.eval()` 到底改变什么

`model.train()` 与 `model.eval()` 不是“是否训练”的总开关，它们会切换某些层的行为：

- `Dropout` 在训练时随机丢弃部分激活，验证时关闭随机丢弃；
- `BatchNorm` 在训练时更新批次统计量，验证时使用已经积累的统计量。

因此训练前应调用 `model.train()`，验证前应调用 `model.eval()`。本例的 `model.train(is_training)` 将两种情况统一起来。

仅调用 `eval()` 还不够。验证时还需要 `torch.no_grad()` 或等价的 `torch.set_grad_enabled(False)`：它阻止 PyTorch 建立反向传播所需的计算图，速度更快、显存更省，也减少误更新风险。`eval()` 控制层行为，`no_grad()` 控制梯度记录；二者职责不同，通常要一起使用。

### 6.3 为什么要按样本数加权 loss

`loss.item()` 是当前 batch 的平均损失。若每个 batch 大小相同，简单平均它们通常没问题；但最后一个 batch 经常更小。正确做法是：

```python
total_loss += batch_loss * batch_size
average_loss = total_loss / total_samples
```

准确率也一样：先累计正确预测样本数，再除以总样本数。这样每个样本拥有相同权重。

### 6.4 checkpoint 应保存什么

只保存 `model.state_dict()` 只能恢复参数，不能严格恢复训练过程。以 AdamW 为例，优化器还维护每个参数的历史动量和二阶矩估计；丢失这些状态后，恢复训练会改变优化轨迹。

本例 checkpoint 包含：

```python
{
    "epoch": 已完成的轮数,
    "model_state": 模型参数,
    "optimizer_state": 优化器内部状态,
    "scheduler_state": 学习率调度器内部状态,
    "best_val_accuracy": 历史最佳验证准确率,
}
```

在真实项目中，还应视需求保存：

- 命令行参数、模型结构版本、代码版本或 Git commit；
- tokenizer、词表、类别到索引的映射；
- 数据集版本、训练/验证划分的样本 ID；
- 混合精度的 `GradScaler` 状态；
- 随机数生成器状态，用于尽量精确的可复现恢复。

不要直接 `torch.save(model, "model.pt")` 当作长期格式。它依赖 Python 类的导入路径，重构代码后容易无法加载；优先保存和加载 `state_dict`。

### 6.5 `last.pt` 与 `best.pt` 为什么都要保存

它们回答不同的问题：

- `last.pt`：训练被打断后，应该从哪里继续？它每轮覆盖，记录最新状态；
- `best.pt`：哪一轮在验证集上的效果最好？它只在验证指标改善时更新。

最终用于预测或交付时，通常加载 `best.pt`，而不是训练结束时的 `last.pt`。这是因为后续 epoch 可能发生过拟合，最后一轮未必最好。

本例采用严格大于 `>` 来更新最佳准确率。若你的主指标是验证损失，则应使用 `val_loss < best_val_loss`；选择主指标必须与任务目标一致。

### 6.6 恢复训练时最容易犯的错

恢复逻辑的关键是 checkpoint 中的 `epoch` 表示“已完成的轮数”。若已经完成 8 轮，下一轮应该是第 9 轮，因此：

```python
for epoch in range(start_epoch, args.epochs):
    ...
```

常见错误包括：

- 只恢复模型，没恢复优化器和调度器；
- 把 `start_epoch` 写成 `checkpoint["epoch"] + 1`，又在循环中重复加一，导致跳轮；
- 忘记恢复历史最优指标，恢复后把较差模型覆盖成“最佳模型”；
- 修改了模型层名称或形状后仍尝试加载旧 checkpoint；
- 改变数据划分、批大小、随机增强策略后，把结果误认为可直接比较。

当模型结构或任务定义发生不兼容变化时，应新开实验目录，而不是强行恢复旧 checkpoint。

## 7. 如何阅读 `metrics.jsonl`

JSONL（JSON Lines）是一行一个 JSON 对象的文件，适合训练过程持续追加，也容易被 Python、pandas 或日志系统逐行处理。文件片段大致如下：

```json
{"epoch": 1, "train_loss": 0.513, "train_accuracy": 0.784, "val_loss": 0.297, "val_accuracy": 0.885, "learning_rate": 0.01}
{"epoch": 2, "train_loss": 0.239, "train_accuracy": 0.925, "val_loss": 0.189, "val_accuracy": 0.930, "learning_rate": 0.01}
```

最少应记录：epoch、训练损失、验证损失、训练指标、验证指标和学习率。进一步可加入耗时、显存、梯度范数、全局 step、数据版本和模型版本。

使用标准库快速查看最佳 epoch：

```python
import json
from pathlib import Path

records = [
    json.loads(line)
    for line in Path("runs/toy_classifier/metrics.jsonl").read_text(encoding="utf-8").splitlines()
]
best = max(records, key=lambda item: item["val_accuracy"])
print(best)
```

观察曲线时，可以按下表初步诊断：

| 现象 | 常见含义 | 优先排查方向 |
| --- | --- | --- |
| 训练损失和验证损失都下降 | 正常学习 | 继续观察，保留最佳 checkpoint |
| 训练损失下降，验证损失上升 | 可能过拟合 | 更多数据、数据增强、正则化、减小模型、早停 |
| 两个损失都几乎不变 | 没学到东西 | 学习率、标签、数据范围、梯度、模型容量 |
| 损失突然变为 NaN/inf | 数值不稳定 | 学习率过大、非法数据、除零、溢出 |
| 验证准确率很高但业务效果差 | 指标或数据有问题 | 类别不均衡、泄漏、指标不匹配、数据划分 |
| 学习率降低后仍无改善 | 已接近瓶颈或流程有误 | 检查数据和标签，再尝试新方案 |

不要只看最后一行日志，也不要仅凭一次运行下结论。对关键实验，至少重复运行并保留配置和数据版本。

## 8. 从玩具例子迁移到真实数据

迁移时通常只需替换三块，而训练闭环保持不变：

1. **数据**：实现真实 `Dataset`，在 `__getitem__` 返回一条输入与标签；
2. **模型**：替换 `Classifier`，确保 `forward` 输出与损失函数匹配；
3. **指标**：按任务增加 F1、MAE、BLEU 等指标，并明确最佳模型的选择依据。

例如图像十分类常见的接口是：

```python
# images: [batch_size, 3, height, width]
# labels: [batch_size]，值在 0 到 9 之间
logits = image_model(images)  # [batch_size, 10]
loss = nn.CrossEntropyLoss()(logits, labels)
```

回归任务则会变化：模型输出一般为 `[batch_size, 1]` 或 `[batch_size]`，标签为浮点数，损失可使用 `nn.MSELoss()` 或 `nn.L1Loss()`；准确率通常不再适用，要改用 MAE、RMSE 或业务容忍误差内的比例。

对于语言模型，输入和标签通常是 token ID，输出形状常为 `[batch_size, sequence_length, vocab_size]`。虽然张量形状、mask 和损失细节更复杂，但“训练与验证分开、保存完整状态、记录可比较指标”的原则不变。

## 9. 初学者高频错误清单

### 9.1 忘记 `optimizer.zero_grad()`

表现：梯度跨 batch 累加，训练不稳定或结果异常。除非你正在有意实现**梯度累积**，否则每个 batch 的反向传播前清空梯度。

### 9.2 在验证阶段调用了 `optimizer.step()`

表现：验证集参与了参数更新，验证指标不再可信。将训练与验证封装成一个函数时，用 `optimizer is None` 明确区分两种模式。

### 9.3 只调用 `eval()`，没有关闭梯度

表现：验证仍会构建计算图，速度慢、显存占用高。用 `torch.no_grad()` 或 `torch.inference_mode()` 包裹验证；后者限制更强，纯推理时通常更省开销。

### 9.4 模型和数据不在同一设备

表现：报错类似 “Expected all tensors to be on the same device”。创建模型后 `.to(device)`，每个 batch 的输入和标签也 `.to(device)`。

### 9.5 交叉熵前手动 `softmax`

表现：数值稳定性变差，学习效果可能受影响。`CrossEntropyLoss` 的输入应是原始 logits。

### 9.6 损失不下降就盲目增加 epoch

表现：浪费时间且掩盖根因。先在很小的数据子集上尝试过拟合：例如只取 32 个样本，确认模型可将训练损失显著降下来。若不能，优先检查标签、数据对齐、损失函数、学习率和参数是否真的被更新。

### 9.7 checkpoint 路径和实验混在一起

表现：新实验覆盖旧实验，或恢复到不匹配的状态。每次实验使用带日期、任务名或配置摘要的独立输出目录。

### 9.8 把验证集结果反复用于调参后仍叫“测试结果”

表现：对真实泛化能力过度乐观。保留从不参与模型选择的测试集，在最后只评估一次。

## 10. 验证你的训练循环是否真的可靠

跑通没有报错不代表训练循环正确。请完成下面的验证闭环：

1. **形状检查**：在第一个 batch 打印 `features.shape`、`labels.shape`、`logits.shape`，确认与模型和损失函数预期一致。
2. **小数据过拟合**：只用几十条训练样本，观察训练 loss 是否能明显下降、训练准确率是否接近 100%。
3. **参数确实更新**：在一次 `optimizer.step()` 前后比较某层权重，确认其有变化。
4. **验证不更新参数**：在验证函数调用前后保存一份 `state_dict` 副本并比较，确认参数不变。
5. **恢复一致性**：先训练 8 轮，记录第 8 轮的 `last.pt`；再用 `--resume` 训练到 20 轮，确认日志从 epoch 9 接续，学习率和最佳指标没有重置。
6. **最佳模型验证**：训练结束后分别加载 `best.pt` 和 `last.pt` 在验证集评估，确认你理解二者可能不同。

一个很实用的调试片段如下：

```python
before = model.layers[0].weight.detach().clone()
# 执行一次正常的训练 batch，包括 backward 和 optimizer.step
after = model.layers[0].weight.detach().clone()
print(torch.equal(before, after))  # 正常训练时应为 False
```

如果参数没有变化，按顺序检查：是否调用了 `loss.backward()`、是否调用了 `optimizer.step()`、优化器是否由 `model.parameters()` 创建、参数的 `requires_grad` 是否为 `True`、损失是否真的依赖模型输出。

## 11. 何时加入进阶能力

先让基础闭环稳定，再按问题引入工具：

- **过拟合**：增加 early stopping，保存验证指标最好的 checkpoint；
- **梯度爆炸**：在 `backward()` 后、`step()` 前使用 `torch.nn.utils.clip_grad_norm_`；
- **显存不足**：减小 batch size，随后理解梯度累积和混合精度；
- **训练慢**：使用 GPU、合理设置 `num_workers`、进行性能分析；
- **实验过多**：使用 TensorBoard、MLflow 或 W&B，但仍保留本地 checkpoint 与可读日志；
- **需要严格复现实验**：记录配置、数据版本、环境版本和随机状态。

例如梯度裁剪的正确位置是：

```python
optimizer.zero_grad()
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
```

梯度累积则不能在每个 batch 都 `zero_grad()` 和 `step()`；它是为了用多个小 batch 模拟一个大 batch，必须同时调整 loss 缩放、更新间隔、日志口径和 checkpoint 的恢复策略。理解基础循环后再使用它。

## 12. 建议的练习顺序

按下面顺序完成，能把“看懂”转为“能独立写”：

1. 不看本文代码，自己写一个单 batch 训练步骤；
2. 用玩具数据写 `run_epoch`，输出训练损失和准确率；
3. 添加验证集，并确认验证函数没有 `backward()` 或 `step()`；
4. 写 `last.pt` 保存和加载，故意中断后恢复；
5. 添加 `best.pt`，分别尝试以验证 loss 和验证 accuracy 为主指标；
6. 将玩具数据替换为 FashionMNIST 或自己的小数据集；
7. 故意制造一个错误，例如删除 `zero_grad()`、给标签错误 dtype、把数据留在 CPU，阅读报错并修复；
8. 为训练函数写一段自动化检查，至少覆盖“空 DataLoader 报错”和“验证不更新模型”。

每次只改变一个变量，并把结果记在日志中。深度学习训练最大的陷阱之一，是同时改了数据、模型、学习率和随机种子，却不知道效果变化来自哪里。

## 13. 总结：可交付的最小训练能力

一个合格的小型 PyTorch 训练循环，不是只有 `loss.backward()` 和 `optimizer.step()`。它至少应做到：

- 训练阶段正确更新参数；
- 验证阶段不更新参数、不记录梯度，并使用正确的层模式；
- 用清晰的平均口径记录损失和任务指标；
- 同时保存最新进度与最佳模型；
- 恢复模型、优化器、调度器、epoch 和最优指标；
- 通过小数据过拟合、日志连续性和 checkpoint 恢复验证流程。

当你能独立完成这个闭环后，再学习 CNN、Transformer、LoRA、混合精度和分布式训练，很多复杂概念都会落到清晰的位置：它们本质上是在扩展数据、模型、数值计算或训练状态，但不会取代这套基本的实验工程纪律。
